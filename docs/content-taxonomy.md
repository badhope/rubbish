# Rubbish 内容分类标准 v1.1（2026-11-16）

> 本文件是内容分类的唯一口径。以后新增稿件、批量重审、导入旧数据，都按这里的定义执行；不要再用「看标题顺眼」或「导入时默认」来分。

## 1. 两个维度，不要混

| 字段 | 取值 | 含义 |
|---|---|---|
| `content_track` | `paper` / `essay` | **文体轨道**：论文轨 / 副刊轨。先判断它是不是论文，再谈学术还是荒诞。 |
| `track` | `serious` / `absurd` | **论文语气**：学术论文 / 荒诞论文。只对 `paper` 有意义；副刊不参与这个二分。 |
| `content_category` | `academic` / `fun` / `rant` | 内容类别。论文轨固定 `academic`；副刊按栏目分 `fun` / `rant`。 |
| `content_genre` | `joke` / `fiction` / `review` / `guide` / `essay` / `poetry` / `rant` | 副刊文体。论文轨必须为空。 |

**硬规则**

1. 论文轨的 `content_category` 只能是 `academic`。
2. 副刊才允许 `content_genre` 非空。
3. `track` 只在 `content_track=paper` 时使用；副刊的 `track` 不再作为质量/等级依据。
4. 分类是编辑判断，不是质量分。不要用 `quality_score` 反推分类。

## 2. 论文轨：学术 vs 荒诞

### 学术型（`track=serious`）

同时满足：

- 提出一个**真实、可讨论的问题**，而不是把玩笑包装成问题；
- 使用**真实材料**：实验、样本、数据、文本、档案、公开案例、政策文本，或可核查的理论论证；
- 论证过程能被同行复核，结论有明确边界与局限；
- 作者没有在摘要/正文中声明「这是戏仿/玩笑/示例数据/不打算当事实」。

题材可以是游戏、动漫、恋爱、网络梗、实验室日常；**题材不严肃不等于论文荒诞**。判断的是问题与证据，不是标题好不好笑。

### 荒诞论文（`track=absurd`）

满足任一：

- 核心命题是**不可能/反常识的戏仿**，作者不打算让它被当作事实；
- 摘要或正文明确说「玩笑/戏仿/讽刺/示例数据/虚构/不能证明」；
- 用论文外壳讨论一个纯段子，材料只是布景，结论不承担知识增量；
- 形式完整但问题是故意荒诞的（如「出生前开始发论文能否提高院士入选率」）。

### 边界规则

- **讽刺但讨论真实问题**：如果论证真实、材料可核查、结论有边界，归学术；如果只是借题玩梗、不提供可核查论证，归荒诞。
- **示例数据/模拟数据**：如果明确是方法演示、且问题真实，可归学术（如计算模拟、思想实验）；如果示例数据只是为了把段子写成论文，归荒诞。
- **不确定时**：先留在 `absurd`，在 `docs/content-taxonomy-review.md` 里登记，不要凭感觉迁 `serious`。

## 3. 副刊轨：什么留在 essay

以下保留 `content_track=essay`：

- 小说、诗歌、笑话、吐槽、随笔、书评、栏目说明、公告、指南、编辑部特写；
- 有 `content_genre` 的稿件（`joke` / `fiction` / `review` / `guide` / `essay` / `poetry` / `rant`）；
- 作者明确以「副刊/随笔/戏仿」自述、且没有论文结构（摘要-方法-结论）的稿件。

以下必须迁 `paper`：

- 有摘要、关键词、方法/数据/结论等论文结构；
- 标题与正文以「研究/分析/模型/实证/综述」为主，而不是栏目/小说/公告；
- 作者把它投到论文轨，只是导入时落到了副刊。

## 6. 以后新增稿件的操作顺序

1. 先判 `content_track`：论文结构 → paper；副刊文体 → essay。
2. 论文再判 `track`：真实问题 + 可核查材料 → serious；戏仿/示例/自认玩笑 → absurd。
3. 副刊填 `content_genre`，不要填 `track` 作为等级。
4. 改完必须复验：列表筛选计数、详情页标签、PDF/Word 下载三条链路。
5. 批量改生产前先查约束、抽 1 条试写；不要直接把线上当试验场。
