# 全站文案长尾盘点（1.20.19）

盘点日期：2026-11-28。范围只包括站方界面、通知、邮件和错误提示；作者标题、正文、评论与用户名保持原文，不进入翻译层，也不在“AI 润色”范围里。

## 盘点口径

- 前端：`apps/frontend/src` 下所有 `extractError(err, '……')` 的兜底文案、`EmptyState` 与 `ErrorState`、按钮和筛选条。
- 后端：`apps/backend/app` 下所有面向用户的 `HTTPException.detail`、通知标题/正文、邮件主题与正文。
- 英文：以 `i18n-dictionary.ts` 与 `i18n.ts` 的精确词条、日期/数量正则为准；缺词条时保留中文，不机器拼接。

## 本轮结果

| 类别 | 数量 | 处理 |
|---|---:|---|
| 前端兜底错误文案 | 101 | 全部保留“失败对象 + 下一步”的结构；后端 `detail` 优先，兜底只在后端无说明时出现 |
| 空状态 / 错误态组件 | 63 | 新页面（领域页、按领域找人、零覆盖面板）补齐；存量继续按页面场景保留 |
| 通知标题/正文模板 | 13 | 逐条检查，均说明“发生了什么 + 点哪里/等多久”；没有只剩“操作失败”的模板 |
| 后端面向用户的通用错误 | 2（改前 4） | 验证码邮件两处改成“检查邮箱、60 秒后再试、或改用密码登录” |
| 邮件主题/正文 | 与通知模板同源 | 不改写作者原文；站方说明保持短句与明确动作 |

## 1.20.19 新增或改写的文案

- 13 个受控方向、42 个细分方向补英文名；领域页正文、搜索页“正在按领域找人 / 进入领域页 / 清除领域筛选”、发现页入口都进英文层。
- 领域页动态人数补单复数：`1 person in this field` / `2 people`，作品数、互评覆盖、订阅人数同样按数量正则处理。
- 验证码邮件失败从“请稍后再试”改为可执行路径：检查邮箱地址、60 秒后重试、或改用密码登录。
- 后台健康新增“审核队列”“通知邮件（24h）”两条检查，说明直接给出待核验数、SLA 超时数、成功/失败数与 5% 阈值。

## 保留策略

- 不把“失败”统一改成“系统开小差了”这类模糊话术；失败对象、可能原因和下一步至少保留两项。
- 不翻译作者写下的标题、正文、评论、用户名和自定义标签。
- 邮件与通知里的匿名互评信息不增加身份线索；文案只说明结果与入口。
