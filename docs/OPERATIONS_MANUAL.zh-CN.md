# 人工运营手册

> 适用范围：Rubbish 主题论坛的半自动化内容流转  
> 更新：2026-11-24

## 一、每天先看什么

后台入口：`/admin/content?section=moderation`。

1. 先看顶部四个数字：待人工核验、待作者修改、已公开、未通过。
2. 再看“待人工核验”队列，默认“风险优先”。
3. 超过预计时限的条目会显示红色的剩余时间，优先处理。
4. 新主题帖被自动公开后仍可能在举报或巡检里出现，按普通举报流程处理。

## 二、单条处理

### 通过

适用：标题、正文、分区、虚构标注都正常，没有隐私或引流风险。

1. 点“通过”。
2. 处理说明可选；建议写一句可追溯的判断，例如“正文为写作复盘，无联系方式”。
3. 确认后主题帖立刻进入公开列表，作者收到“已通过核验”通知。

### 要求修改

适用：正文有价值，但需要删联系方式、补来源、改标题、换分区、加虚构标注。

1. 点“要求修改”。
2. 至少写 4 个字，说明具体要改什么；不要写“改一下”这种无法执行的话。
3. 主题帖保持隐藏，作者可原帖修改；修改后自动重新进入人工核验。
4. 作者收到通知，说明会显示在通知正文里。

### 不通过

适用：广告引流、辱骂、站规禁止内容、明显不属于主题论坛的内容。

1. 点“不通过”。
2. 写清内容层面的原因，不公开作者隐私信息。
3. 主题帖保持隐藏；作者仍可看到处理说明，修改后重新提交。

## 三、批量处理

1. 在当前页勾选条目，或点“全选本页”。
2. 选择“批量通过 / 批量要求修改 / 批量不通过”。
3. 批量通过可留空说明；批量要求修改和不通过必须写至少 4 个字。
4. 一次最多 50 条；超过请拆批。
5. 批量操作前先确认选择数量，避免把“要求修改”误点成“通过”。

批量只处理当前已勾选的 ID；翻页后选择不会自动扩展到其他页。

## 四、处理记录与审计

每条主题帖的“处理记录”会显示：

- 动作：提交、重新提交、通过、要求修改、不通过。
- 前后状态。
- 操作人；系统规则触发的显示“系统/规则”。
- 处理说明与时间。

审计事件只追加，不提供删除入口。需要更正判断时，再发一次处置并写清原因，不修改历史记录。

## 五、前台运营快捷面板

有编辑及以上权限的账号，在主题帖详情页右下角会看到盾牌按钮：

- “立即核验这条主题帖”：跳到后台核验队列并定位该帖。
- “主题巡检与置顶”：跳到主题巡检页。

普通读者和作者看不到这个按钮；即使伪造入口，后端仍会按权限拒绝。

## 六、作者侧状态说明

| 状态 | 作者看到 | 公开可见 |
|---|---|---|
| `published` / `auto_approved` / `approved` | 已公开 | 是 |
| `manual_review` | 已进入人工核验，预计 X 分钟 | 否 |
| `changes_requested` | 需要调整，附运营说明 | 否 |
| `rejected` | 未通过核验，附运营说明 | 否 |

作者修改标题或正文后，主题帖重新进入 `manual_review`，预计时限按当前规则重新计算。

## 七、规则设置

仅主编或管理员可以打开“规则设置”。

可调项：

- 自动发布开关：关闭后所有新主题帖进入人工核验。
- 人工阈值：默认 40，越低越严格。
- 预计时限：默认 30 分钟，前台按这个值显示。
- 四项风险权重：联系方式、站外链接、信息量偏低、格式异常；设 0 可关闭单项。

调整前先看 `docs/AUTOMATION_RULES.zh-CN.md` 的场景建议。调整后观察一个班次，不要连续大幅摆动。

## 八、超时与异常

### 队列积压

1. 先按“等待最久”排序，清理最早条目。
2. 如果是规则过严导致大量正常帖入队，临时下调阈值或降低对应权重；记录调整原因。
3. 如果是活动期恶意内容集中，关闭自动发布并通知主编。

### 通知未收到

1. 检查作者通知偏好是否关闭了站内通知。
2. 检查后台处置是否成功；处理记录里有事件才说明主事务已提交。
3. 仍无法解释时，按故障升级，不直接改数据库补通知。

### 服务异常

1. 健康检查：`curl -fsS -H 'Host: rubbish.argjiemi.cn' http://127.0.0.1:8080/api/health`。
2. 服务状态：`systemctl status rubbish-app --no-pager`。
3. 最近日志：`journalctl -u rubbish-app -n 100 --no-pager`。
4. 不要在生产库手工改表；先备份、再迁移、再复验。

## 九、禁止操作

- 不替作者重写正文；用“要求修改”说明问题。
- 不把作者邮箱、IP、设备信息写进处理说明。
- 不用批量通过处理没看过的内容。
- 不在没有备份的情况下执行迁移或手工 SQL。
- 不删除审计事件来“美化”处理记录。

## 十、交接清单

每班结束前确认：

- [ ] 待人工核验队列没有超过预计时限的条目，或已升级。
- [ ] 批量处置没有遗留半完成状态。
- [ ] 规则改动有记录、有原因。
- [ ] 异常与投诉已写进交接备注。
