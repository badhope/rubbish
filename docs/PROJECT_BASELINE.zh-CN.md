## 一、当前核心状态

### 1. 产品定位

Rubbish 是自托管的公开写作与主题交流社区。长文进入内容库，短讨论进入主题论坛；网站不提供学术评价，也不出具职称、学分、学历等机构证明。

### 3. 论坛内容流转

主题帖发布后先走确定性规则引擎：

1. 硬规则命中：直接拒绝，返回可读原因。
2. 风险分低于人工阈值且自动发布开启：进入公开列表。
3. 风险分达到阈值、命中模糊边界或关闭自动发布：进入 `manual_review`，同时生成预计核验时间。
4. 运营在后台核验队列中通过、要求修改或不通过；所有处置写审计事件并通知作者。
5. 作者修改正文后重新进入人工核验，避免“先通过、再改成广告”。

当前链路不依赖大模型。规则引擎负责可解释的初筛，人工负责边界判断、内容修正和最终分发。

## 二、已交付功能清单

### 内容与阅读

- 作品发布、修订、下载、分享、收藏、阅读进度、作者关注。
- 内容库按话题、年份、分区筛选；合集按阅读顺序编排。
- 全文搜索、标签页、公开状态页、可访问性说明、Atom feed。
- 作品正文、公开邮箱、图源与文献说明已完成批量整理；11 篇标题与正文错配已修复。

### 投稿与审稿

- 作者四步发布向导、服务端草稿、版本快照与版本历史。
- 编辑内容台按 `pending / under_review / major_revision / minor_revision / rework_requested / resubmitted` 分页签；「待修改」可查作者是否仍在改。
- 编辑「退回作者修改」：作品进入 `rework_requested`，只通知作者逐条要求；本轮互评任务立即撤回并通知相关互评成员。作者可改内容、换文件、显式重交；重交后进入 `under_review`，旧一轮指派作废并重新分派。
- 作者端「待修改」卡片、页签与按钮闭环：修改作品 → 保存 → 重新提交修改稿，未保存直接重交会明确提示会与上一版相同。

### 异常与提醒

- 全局诊断卡片：API 最终失败、限流、超时、断网、未捕获异常与未处理 Promise 都显示紧凑卡片，含可能原因、建议下一步、method/path/status/request_id、页面和时间；可复制诊断或跳转 `/status`。
- 成功提示保持轻量 toast；错误/警告 toast 自动升级为诊断卡片。后台轮询同一页面重复失败每分钟只弹一次，隐藏标签页不弹。
- 通知弹窗为 `70vh`、`max-w-xl` 紧凑卡片，保留键盘滚动与滚动链隔离。
- 发信池：官方主账号优先；单账号在途达到上限时新邮件立即溢出到待命备用账号；连续失败熔断后冷却，冷却结束自动恢复。管理端系统健康显示各账号在途、连续失败与冷却时间。

### 主题论坛

- 树形分区；无分区时按标题与正文做保守自动归类。
- 发主题帖、楼层互动、举报、关注、通知、分享。
- 三步骤发布提示：写主题帖 → 预览确认 → 自动流转。
- 正文与标题本机草稿自动保存，显示最近保存时间；提交作品向导另有本地 + 服务端双草稿。
- 公开列表、详情、楼层互动只展示已公开主题帖；作者与运营仍可查看未核验内容。
- 作者在待核验、要求修改、未通过状态下看到明确状态条与预计时限。

### 半自动化运营

- 规则信号：疑似联系方式、站外链接、信息量偏低、格式异常；硬规则：广告引流、辱骂攻击、站规词。
- 人工核验队列：风险优先、等待最久、最新提交三种排序；按状态筛选。
- 单条与批量处置：通过、要求修改、不通过；处置说明至少 4 字（通过可选）。
- 审计事件：提交、重新提交、通过、要求修改、不通过；记录操作人、前后状态、说明与时间。
- 规则设置：自动发布开关、人工阈值、预计时限、四项风险权重；仅主编或管理员可改。
- 作者通知：处置结果写入站内通知，点击可回到主题帖。
- 前台运营快捷面板：有权限的运营在主题帖详情页一键跳到该帖核验记录或主题巡检。

### 全站体验

- 页面切换与模块跳转使用统一过渡；已有错误边界、空状态、加载态与友好错误提示。
- 新手引导首次访问自动出现，可跳过；补充了主题论坛三步骤与自动保存说明。
- 统一术语：主题帖、楼层互动、主题论坛、分区；不再用泛化的“帖子/评论/讨论区”描述论坛核心对象。
- 全站可切换中英文：右上角常驻语言按钮，支持 `?lang=en` 与浏览器语言自动判断；英文为人工润色的站方文案。作者标题、正文、评论与用户名保持原文，不经过翻译层。

## 五、人工运营干预权责清单

权限档位以 `users.role` 与历史角色合并后的最高档为准：`user < reviewer < editor < editor_in_chief`；管理员视同最高档。

| 角色 | 可查看核验队列 | 单条处置 | 批量处置 | 修改规则阈值 | 查看审计 | 典型场景 |
|---|---|---|---|---|---|---|
| 管理员 | 是 | 是 | 是 | 是 | 是 | 故障处置、权限兜底、规则回滚 |
| 主编 / 副主编 | 是 | 是 | 是 | 是 | 是 | 规则调整、争议内容终审、SLA 升级 |
| 编辑 / 分区整理 | 是 | 是 | 是 | 否 | 是 | 日常核验、批量清理、要求作者修改 |
| 互评成员 | 否 | 否 | 否 | 否 | 否 | 只参与作品互评，不处理论坛审核 |
| 作者 | 只看自己的主题帖状态 | 否 | 否 | 否 | 只看自己的处置说明 | 修改正文后重新提交 |
| 访客 | 只看已公开主题帖 | 否 | 否 | 否 | 否 | 浏览与阅读 |

### 处理时效

- 默认预计时限 30 分钟；后台可按运营阶段调整到 1–1440 分钟。
- 超过预计时限仍未处置：运营应在当班内升级给主编；当前版本为人工观察，自动升级提醒在 P1 任务池。
- 批量处置一次不超过 50 条；超过时拆批，避免误操作面过大。

### 操作边界

- 不修改作者正文替作者“洗稿”；需要改内容时使用“要求修改”，说明具体问题。
- 不公开作者邮箱、IP、设备信息；处置说明只写内容层面的原因。
- 通过前确认标题、正文、分区、虚构标注；涉及真人隐私、站外引流、联系方式优先要求修改。
- 规则阈值调整必须记录原因；调整后观察一个班次的队列量与误判，不连续大幅摆动。

## 六、无大模型环境下的能力边界

### 能自动处理

- 明确的广告引流、辱骂攻击、站规词：确定性关键词与正则命中。
- 疑似联系方式、站外链接、信息量偏低、全大写/感叹号过多：可解释信号加权。
- 自动归类到保守分区：标题与正文关键词匹配。
- 风险分、人工阈值、预计时限、审计事件、作者通知：数据库与接口闭环。

### 不能自动处理

- 反讽、隐喻、上下文中的暗示和圈层黑话。
- 图片、音频、视频内容审核；当前规则只看文本。
- 跨帖串联、团伙引流、长期行为模式。
- 事实核查、版权判断、隐私细节识别。
- 语义级“是否切题”“是否有价值”的判断。

这些边界必须由人工补位。规则引擎的价值是缩小人工阅读面，不是替代判断。
