## 写文档的原则

- 写给“马上要做这件事的人”，不要写成发布通稿。
- 一个文件只讲一件事。需要目录的文档，通常该拆了。
- 命令放在可复制的代码块里，并写清楚在哪个目录执行。
- 同一套架构不要在三份文档里各讲一遍，能链接就链接。

`docs/archive/legacy-2026-11/` 是早期产品形态的历史资料，只为追溯保留，不再维护，也不要当成当前文档使用。
